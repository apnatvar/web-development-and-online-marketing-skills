# Chrome Web Store listing assets

Use current Chrome Web Store dashboard limits and requirements before finalizing a listing. Requirements can change.

## Listing copy

- Keep the description useful and factual, and within 16,000 characters including spaces, line breaks, and URLs. Prefer concise copy over padding. If an exact count is requested, count the complete final text and make no unsupported claims.
- A character limit is not a word-count target. Describe the purpose, core features, permissions or data use users should understand, and relevant limitations in plain language.
- Keep the store description, extension behavior, support site, privacy policy, and dashboard privacy fields consistent.

## Screenshots

- Default to two screenshots unless the user asks for a different count. Chrome allows one to five; 1280×800 is preferred, while 640×400 is supported. Verify the exported image’s physical dimensions because CSS display size may differ from the file size.
- Show the real production interface and representative actions. Use real example or public URLs when useful. Do not fabricate successful states or present AI-generated screens as genuine product screenshots.
- If a fixture, mock, or test shim is needed to capture a state, disclose that provenance and label the image as illustrative. Capture actual actions and outcomes.
- Keep screenshots full-bleed with square corners. Check that text remains readable at the store’s displayed size; use supported cropping rather than altering the interface to imply behavior it does not have.

## Icons and promotional art

- Include the required 128×128 PNG extension icon in the extension package. Chrome’s icon guidance recommends a 96×96 artwork area with 16 pixels of transparent padding on each side for square artwork. Check the small-size appearance and contrast on light and dark backgrounds.
- Provide a 440×280 small promotional tile; it is required for a store listing. A 1400×560 marquee image is optional. Follow current dashboard requirements for any other asset types.
- Keep the store artwork aligned with the product’s real branding and interface. Avoid screenshots or decorative claims that imply features the extension does not provide.

## Privacy and permissions

- Base privacy practices and permission justifications on the actual release package and data flows. Disclose relevant locally processed or stored user data as well as data transmitted to the developer or another recipient.
- Do not fill gaps with made-up dashboards, policy claims, collection practices, or support channels. Check the live Chrome Web Store policy pages because requirements change.
