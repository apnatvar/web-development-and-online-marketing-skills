# Drafting

## Draft in passes

1. Write the governing claim and intended action.
2. Outline the minimum logic: context, tension, claim, mechanism, proof, objection, action.
3. Apply the audience's awareness level.
4. Apply the selected platform adapter.
5. Add only verified specifics and clearly labeled placeholders.
6. Restore brand voice using supplied samples.
7. Separate the reader artifact from all production notes before editing.

Lead with the main point unless discovery, suspense, or low awareness genuinely requires a short setup. Keep each section doing one job. Place proof near the claim it supports.

## Voice preservation

Infer observable traits: sentence length, formality, vocabulary, humor, point of view, rhythm, punctuation, and tolerance for hype. Preserve these without copying irrelevant mistakes. When no samples exist, use a clear, direct, restrained default.

## Variant discipline

Generate variants by changing one named dimension:

- awareness level;
- opening mechanism;
- strategic angle;
- emotional stake;
- proof type;
- CTA commitment;
- tone.

Do not label near-duplicates as strategic alternatives.

## Unknowns

Use placeholders only where the user can supply the truth: `[verified metric]`, `[customer example]`, `[integration name]`. Never make placeholders look publish-ready.

## Reader-facing boundary

After drafting, inspect every line as if the intended reader encountered it without context. Ask: **Would a human author deliberately write this for that reader, or is it really an instruction, explanation, caveat, or status note for a superior, reviewer, user, or production team?**

Delete the second category from the reader artifact. This includes prompt language, workflow steps, rationale, framework names, drafting commentary, approval requests, file instructions, validation results, audience labels, and phrases such as â€œinsert X hereâ€ unless the output is explicitly an unfilled template. Do not conceal internal material in comments, metadata, alt text, captions, or formatting.

When handoff context is necessary, finish the reader-facing copy first, then add a distinctly labeled `Handoff notes` section outside it. Never interleave notes with copy or make them easy to publish accidentally.
