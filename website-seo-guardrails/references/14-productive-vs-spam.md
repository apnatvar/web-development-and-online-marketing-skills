# Productive Work Versus SEO Busywork and Spam

Use this file whenever a proposed tactic sounds scalable, fast, or metric-driven.

| Sounds productive | Why it is weak/risky | Productive alternative |
| --- | --- | --- |
| Publish hundreds of AI posts to cover every query | Scaled commodity content and incoherent site focus | Publish fewer expert-led pages with original evidence and measured demand |
| Create a page for every city + service | Doorway risk when differences are token substitutions | Build real location pages only for distinct operations/evidence; use a service-area hub otherwise |
| Turn every glossary term into a URL | Thin definitions create index bloat | Build a strong glossary hub; index only deep, useful concept guides |
| Index every course lesson | Repetitive generated lessons compete and dilute quality | Index course/module hubs; allowlist substantively authored standalone lessons |
| Copy vendor tool descriptions into a directory | Scraped/affiliate-like commodity pages | Add first-hand tests, use cases, limits, methodology, review dates, and original data |
| Add every schema type possible | Invalid/misleading markup risks rich-result actions | Add only supported, visible, accurate primary-content markup |
| Request indexing every day | Submission does not improve quality or guarantee indexing | Fix discovery/value issues; submit only new/materially changed canonical URLs |
| Ping IndexNow with the whole sitemap repeatedly | Creates noise and wastes monitoring attention | Trigger deduplicated add/update/delete notifications |
| Buy “high-DR” backlinks or guest-post packages | Link spam and irrelevant metric chasing | Earn editorial links through useful assets, research, tools, and relationships |
| Repeat exact-match anchors internally/sitewide | Unnatural, poor UX, and limited informational value | Use descriptive varied anchors in relevant context |
| Expand articles to an arbitrary word count | Filler does not create value | Cover the task completely and stop |
| Change dates to look fresh | Misleads users when content did not change | Update facts/evidence substantively and record changes |
| Add `llms.txt` and special AI schema to “rank in AI” | Google says these are not required; can distract from fundamentals | Make indexable, snippet-eligible, non-commodity content with clear sources |
| Chase 100/100 audit scores | Tools contain low-impact and heuristic warnings | Fix P0/P1/P2 issues by real evidence, affected URLs, and business impact |
| Create several properties/streams to repair GA4 | Fragments data and hides implementation faults | Fix event taxonomy, tagging, filters, consent, and documentation |
| Mark every click as a conversion/key event | Inflates success and destroys decision value | Mark only meaningful business outcomes |
| Add many above-the-fold ads for RPM | Hurts UX, performance, trust, and policy safety | Start with restrained responsive placements and measure content outcomes |
| Publish filler articles to meet an “AdSense minimum” | No universal count; increases thin-content risk | Finish the site and publish a coherent body of genuinely useful content |
| Disavow every suspicious backlink | May discard useful signals without evidence | Investigate manual actions/history and use disavow only when justified |

## Agent behavior

Do not convert an observation into a large publishing program without validating user need, site focus, editorial capacity, and policy risk. Challenge vanity metrics, false precision, universal checklists, and ranking guarantees. Explain when the safest recommendation is to merge, `noindex`, delay, or not create a page.
